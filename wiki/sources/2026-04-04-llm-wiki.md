# LLM Wiki — Karpathy (2026-04-04)

## Summary

Karpathy's pattern replaces per-query RAG with a **persistent, LLM-maintained wiki** that compounds: raw sources are immutable, the wiki is a structured interlinked markdown layer kept current by the LLM, and a schema file disciplines the LLM's ingest/query/lint workflows.

## Details

### Core Idea — Persistent compounding artifact vs RAG

- RAG retrieves chunks at query time and re-derives answers from scratch; no accumulation, poor synthesis across 5+ docs.
- LLM Wiki: LLM **incrementally builds and maintains** a wiki between user and raw sources — extracts, integrates, updates entity/concept pages, revises syntheses, flags contradictions. Cross-refs, contradictions, synthesis are already compiled, not re-derived.
- Metaphor from gist: *LLM is programmer, Obsidian is IDE, wiki is codebase*. Human curates sources & asks questions; LLM does summarization, cross-referencing, filing, bookkeeping.

### Applicability

- Personal (goals, health, journal), Research (papers over months), Book companion wiki (Tolkien Gateway-style), Team (Slack/transcripts → internal wiki), plus competitive analysis, due diligence, trip planning, courses, hobbies.

### Architecture — Three Layers

1. **Raw sources** — immutable curated documents (articles, papers, images, data). LLM reads only.
2. **The wiki** — LLM-generated markdown directory: summaries, entities, concepts, comparisons, overview. LLM owns entirely.
3. **The schema** — `CLAUDE.md`/`AGENTS.md` that tells LLM structure, conventions, workflows. Co-evolved with human.

### Operations

- **Ingest**: drop source → LLM reads, discusses takeaways, writes `wiki/sources/<slug>.md`, updates 10-15 pages (entity/concept/overview), updates `index.md` + `log.md`, shows diff. Prefer one-at-a time with human in loop; batch possible. Team-scale lesson: concurrent ingests fork unless `index.md` placeholders (`status: planned`, `claimed_by` set, atomic conditional write) reserved before generation.
- **Query**: LLM reads `index.md` first, then full-text search, union of both; reads top-k wiki pages; synthesizes with citations; offers markdown/table/Marp/matplotlib/canvas; ask "file back into wiki?" → `wiki/questions/` or `wiki/syntheses/`.
- **Lint**: health-check for contradictions, stale claims, orphans, stubs, mentioned-but-missing concepts, duplicate near-concepts, missing cross-refs, data gaps, copied-state drift. Output `wiki/syntheses/lint-YYYY-MM-DD.md` + log entry.

### Indexing & Logging

- **index.md** — content-oriented catalog: every page with 1-line summary + metadata, organized by category. Works to ~100 sources/hundreds of pages without embeddings. Team-scale fix: add BM25 full-text and take union with index — never index-only.
- **log.md** — chronological append-only, prefix `## [YYYY-MM-DD] <op> | <title>` parseable via `grep "^## \[" | tail`.

### Optional CLI

- Local search: naive BM25 script or `qmd` (hybrid BM25/vector + LLM rerank, on-device, CLI + MCP). Install when >100 sources / >200 pages.

### Tips & Tricks

- Obsidian Web Clipper → `raw/sources/`; attachment path `raw/assets/` + hotkey `Ctrl+Shift+D` to download images locally; graph view for shape; Marp for slides; Dataview for frontmatter queries; vault is git repo.

### Why It Works

- Knowledge-base maintenance is bookkeeping-heavy and humans abandon wikis; LLMs don't get bored, touch 15 files in one pass, near-zero maintenance cost. Related to Bush's Memex (1945) — private curated knowledge store with associative trails; LLM solves the maintenance problem.

### Lessons from Team Scale (comments on gist)

- Concurrent ingest duplication (~38% near-duplicates) fixed via placeholders + atomic writes.
- Visibility labels (`audience: internal`) leak via stale derivation — compile second wiki by construction instead.
- Index lossiness fixed via union with full-text search.
- Human pins (`wiki/.pins.json`, claim + anchor) must survive recompilation; test re-application.
